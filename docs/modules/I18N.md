# Internationalization (i18n) Documentation

Vestio supports French (`fr`) and Arabic (`ar`) with full RTL (right-to-left) support for Arabic.

## Configuration

### Locales (`src/i18n/config.ts`)

```typescript
export const locales = ['fr', 'ar'] as const;
export type Locale = (typeof locales)[number];
export const defaultLocale: Locale = 'fr';

export const LOCALE_COOKIE = 'vestio_locale';

export function isLocale(value: string | undefined): value is Locale {
  return Boolean(value) && locales.includes(value as Locale);
}

export function localeDirection(locale: Locale): 'ltr' | 'rtl' {
  return locale === 'ar' ? 'rtl' : 'ltr';
}

export const localeNames: Record<Locale, { label: string; short: string; native: string }> = {
  fr: { label: 'Français', short: 'FR', native: 'Français' },
  ar: { label: 'Arabe', short: 'AR', native: 'العربية' },
};
```

## Setup

### Next.js Config (`next.config.ts`)

```typescript
import createNextIntlPlugin from 'next-intl/plugin';

const withNextIntl = createNextIntlPlugin('./src/i18n/request.ts');

export default withNextIntl(nextConfig);
```

### Request Configuration (`src/i18n/request.ts`)

```typescript
import { getRequestConfig } from 'next-intl/server';
import { cookies } from 'next/headers';
import { defaultLocale, isLocale, LOCALE_COOKIE } from './config';
import { getDictionary } from './dictionaries';

export default getRequestConfig(async () => {
  const cookieStore = await cookies();
  const cookieLocale = cookieStore.get(LOCALE_COOKIE)?.value;
  const locale = isLocale(cookieLocale) ? cookieLocale : defaultLocale;

  return {
    locale,
    messages: getDictionary(locale),
  };
});
```

## Usage

### In Server Components

```typescript
import { getTranslations } from 'next-intl/server';

export default async function Page() {
  const t = await getTranslations();
  return <h1>{t('home.title')}</h1>;
}
```

### In Client Components

```typescript
'use client';
import { useTranslations } from 'next-intl';

export default function Component() {
  const t = useTranslations();
  return <button>{t('common.submit')}</button>;
}
```

### Getting Current Locale

```typescript
// Server
import { getLocale } from 'next-intl/server';
const locale = await getLocale();

// Client
import { useLocale } from 'next-intl';
const locale = useLocale();
```

## Language Switching

### LanguageSwitcher Component (`src/components/layout/LanguageSwitcher.tsx`)

Features:
- Dropdown with available locales
- Sets cookie `LOCALE_COOKIE`
- Updates `document.documentElement.lang` and `dir`
- Calls `router.refresh()` to reload with new locale
- Persists choice for 1 year

```typescript
const selectLocale = (next: Locale) => {
  if (next !== locale) {
    const maxAge = 60 * 60 * 24 * 365;
    document.cookie = `${LOCALE_COOKIE}=${next};path=/;max-age=${maxAge};samesite=lax`;
    document.documentElement.lang = next;
    document.documentElement.dir = localeDirection(next);
    router.refresh();
  }
  setOpen(false);
};
```

## RTL Support

- Root layout sets `dir={localeDirection(locale)}` on `<html>`
- Use logical CSS properties where possible (`start`/`end` instead of `left`/`right`)
- Tailwind supports RTL with logical properties
- Test Arabic layout for proper RTL behavior

## Best Practices

### Translation Keys
- Use nested keys for organization: `header.login`, `home.hero.title`
- Keep keys descriptive and consistent
- Avoid hardcoding strings in components

### Adding New Translations
1. Add keys to both French and Arabic dictionaries
2. Use `t()` in components
3. Test in both locales

### RTL Considerations
- Use `ms-auto`, `me-4`, `ps-4`, `pe-4` instead of `ml-`, `mr-`, `pl-`, `pr-`
- Use `text-start`/`text-end` instead of `text-left`/`text-right`
- Icons may need flipping in RTL (or use logical directions)
- Test layouts in Arabic

### Server vs Client
- Prefer server-side translations when possible
- Use client hooks only in interactive components

### Cookie Persistence
Locale preference is stored in cookie and read server-side, ensuring correct initial render.
